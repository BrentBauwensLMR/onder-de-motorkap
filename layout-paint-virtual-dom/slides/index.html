Deel 1

De rendering pipeline

Wat gebeurt er tussen "DOM gewijzigd" en "pixel op scherm"?

Wat is de rendering pipeline?

De vaste stappen die de browser doorloopt om HTML en CSS om te zetten in pixels.

Parse→Style→Layout→Paint→Composite

Niet één keer, maar bij elke wijziging opnieuw.

Een wijziging stapt ergens in, en alles erna moet opnieuw.

Onthoud vooral de tweede zin: hoe vroeger een wijziging instapt, hoe meer werk. Daar komen we op het einde van dit deel op terug.

  • HTML wordt de DOM
  • CSS wordt de CSSOM
  • Gebeurt bij het laden, en bij innerHTML
De browser leest tekst en maakt er objecten van. Dat is de DOM die je vanuit JavaScript aanspreekt. Een appendChild of classList.add wijzigt die boom rechtstreeks, zonder opnieuw te parsen.

Style: welke regels gelden?


/* browser-default */
h3 { font-size: 1.17em; margin: 1em 0; }
/* onze CSS */
h3 { font-size: 24px; line-height: 32px;
     margin: 0 0 8px; }

↓


h3 (computed):
  font-size:   24px
  line-height: 32px
  margin:      0 0 8px
  color:       rgb(34, 34, 34)
  display:     block
  • Selectors matchen, cascade toepassen
  • Resultaat: één computed style per element
  • DevTools: Recalculate Style
Voor elk element beslist de browser welke waarde wint. Een class toevoegen of verwijderen start hier. Te zien in de Performance-tab als "Recalculate Style", en in het Computed-paneel van Elements.

Layout: waar staat elke box?

Bestelling #42

article x0 y0 300×108 h3 x16 y16 268×32 button x16 y56 96×36
  • Breedte, hoogte en positie van elke box
  • Hangt van elkaar af: de button staat onder de h3
  • Wordt de titel 2 regels? Dan schuift alles eronder op
  • DevTools: Layout
Rekensom: 16 padding + 32 titel + 8 marge = 56, daar begint de knop. 56 + 36 + 16 padding = 108 hoogte. Het punt: boxes hangen van elkaar af. Eén maat wijzigen kan de posities van veel andere boxes veranderen. Daarom is layout de dure stap.
Parse→Style→Layout→Paint→Composite

Paint: een lijst tekenopdrachten


// vereenvoudigd
drawRoundRect(0, 0, 300, 108, r=8, white)
drawText("Bestelling #42", 16, 40, 24px)
drawRoundRect(16, 56, 96, 36, r=6, teal)
drawText("Details", 34, 79, 16px, white)
  • In welke volgorde teken je wat?
  • Nog geen pixels: een display list
  • Pixels komen pas bij raster, meestal op de GPU
  • DevTools: Paint, en Rendering → Paint flashing
Veel bronnen zeggen "paint = pixels tekenen". In Chromium maakt paint een lijst opdrachten; raster zet die later om in pixels, in tegels, meestal op de GPU. web.dev telt raster bij paint, Chromium niet. Vandaar dat bronnen elkaar soms lijken tegen te spreken.
Parse→Style→Layout→Paint→Composite

Composite: layers op elkaar leggen

Layer 1: pagina + kaartje
Layer 2: de knop
will-change: transform
  • De pagina is opgedeeld in layers
  • De compositor legt ze op elkaar tot één frame
  • Een layer verschuiven of doorzichtig maken kan zonder opnieuw layout of paint
  • En de compositor heeft een eigen thread: hij wacht niet op JavaScript
  • DevTools: Layers-paneel, Rendering → Layer borders
Denk aan transparante vellen die je op elkaar legt. Heeft de knop een eigen layer, dan kan je hem verschuiven zonder de rest opnieuw te tekenen. De compositor draait niet op de main thread. Daarom bleef het groene bolletje uit de intro lopen.

Terug naar de bolletjes: left heeft de main thread nodig, transform niet.

Dit is de kern van deel 1. Hoe vroeger een wijziging instapt, hoe meer stappen opnieuw moeten. Nuance: of een transform echt alleen composite is, hangt af van of het element al een eigen layer heeft. Dat bekijken we in deel 3.

Zelf zien

  1. DevTools → Rendering → Paint flashing aan
  2. Klik elke knop: wat flitst groen?
  3. Performance → opnemen → per knop kijken naar Layout en Paint
Verwachting: width geeft layout en paint, kleur alleen paint, transform geen van beide. De box heeft will-change: transform, zodat hij vooraf een eigen layer heeft. Nog te controleren in de huidige Chrome-versie voor we dit live tonen.

Wat neem je mee uit deel 1

  • Pixels komen uit een vaste keten: Style → Layout → Paint → Composite
  • Een wijziging stapt ergens in, alles erna moet opnieuw
  • Animeer transform en opacity, niet width, top of left
  • JavaScript, style, layout en paint delen één main thread; de compositor niet

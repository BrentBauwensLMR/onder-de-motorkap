Deel 1

Wat is de rendering pipeline?

De vaste stappen die de browser doorloopt om HTML en CSS om te zetten in pixels.

Parse→Style→Layout→Paint→Raster→Composite

Niet één keer, maar bij elke wijziging opnieuw.

Een wijziging stapt ergens in, en alles erna moet opnieuw.

Onthoud vooral de tweede zin: hoe vroeger een wijziging instapt, hoe meer werk. Daar komen we op het einde van dit deel op terug.

De pipeline in slow motion

We volgen één kaartje door elke stap, en kijken telkens wat er na die stap in de browser bestaat.

Open de app →

Open de app in een nieuw tabblad en doorloop Parse, Style, Layout, Paint, Raster en Composite. Benadruk bij Paint: dat maakt nog geen pixels, maar een display list. Raster maakt er pixels van. Benadruk bij Composite: de compositor heeft een eigen thread. Daarom blijven transform-animaties vlot, ook als JavaScript bezig is.

Wat neem je mee uit deel 1

  • Pixels komen uit een vaste keten: Style → Layout → Paint → Raster → Composite
  • Een wijziging stapt ergens in, alles erna moet opnieuw
  • Animeer transform en opacity, niet width, top of left
  • JavaScript, style, layout en paint delen één main thread; de compositor niet
